## Understanding
M6 measured a 35% autopsy fallback on replayed days; the dominant cause (K-24) is the model stating the wrong state of a nudge when the facts say `shown 1, ignored 1` (it writes "was snoozed"). The training data explains it: ignored-only nudge configs are rare in the data (about 17 of 373 autopsies), although in real use most nudges go unanswered; and 32 training autopsies carry wrong-direction 7-day comparisons or other slips the strict checks catch (K-08). Fix the data, retrain, accept the new model only if it measurably beats run1.

## Approach
1. **`training/clean.py`** (pure functions + CLI, pytest-covered):
   - Drop training autopsies that fail `strict_autopsy_errors` (K-08).
   - The nudge sentence lives alone in paragraph 4 of the autopsies (361 of 373; verified), so rewrite it from `facts.nudges` with a canonical sentence (two phrasings; the first is the M5 template's), which makes every kept example correct by construction.
   - Augment: ~160 variants of existing (clean) examples with a different `nudges` object, weighted to what real use produces (all ignored 40%, mixed 30%, all accepted 15%, snoozed 15%), changing only that paragraph; no other paragraph mentions nudges (verified). Variants keep T1's validators green.
   - Naming examples untouched. Output `data/train_v2.jsonl`; `eval.jsonl` untouched (held out). Extra held-out check set `data/eval_nudge.jsonl`: 40 eval autopsy facts with ignored-heavy nudges (prompts only).
2. **Retrain** with the unchanged recipe (`finetune.py --train data/train_v2.jsonl --tag run2`, LoRA r16/α32, lr 2e-4, 3 epochs).
3. **Export** with `export_onnx.py` (genai 8-bit, same path as run1) and run the browser test page on the 100 eval prompts and the 40 nudge prompts for run1 and run2.
4. **Compare** run1 vs run2 with T2's automatic metrics (valid JSON, grounding, structure, word count, strict-clean) on both sets; paired counts. **Ship rule:** run2 replaces run1 only if autopsy strict-clean on the nudge set improves clearly and the 100-example metrics don't regress (naming valid/grounded/label within 2 points; autopsy valid, grounded and outside-browser zero as before). No judge run (the 31B teacher isn't started for this); judge numbers stay T2's.
5. If run2 ships: point `copy-model.mjs` at it, re-run `probe:m6` and record the new fallback rate; if not, record why and keep run1.

## Interfaces and data
No `shared/` change. Student prompt unchanged. New files: `training/clean.py`, `training/tests/test_clean.py`, `docs/showcase/T3/`.

## Test plan
pytest: nudge sentence builder (all state combos pass `check_autopsy`-style strict checks), paragraph replacement, augmentation keeps validators green and only changes paragraph 4, strict-error drop, deterministic with a seed. Browser metrics as above; `probe:m6` if shipped.

## Risks
Retraining could regress naming (mitigated: naming data unchanged, ship rule); canonical nudge sentences make that part of the autopsy templated (an accepted trade-off, stated in the post); ~35 min of compute.

## Out of scope
