## Understanding
Produce ~1,000 training examples for the two Gemma 3 270M tasks (territory naming + label, ~600; autopsy, ~400), written by the local Gemma 4 31B teacher and filtered by shared validators. Inputs are generated programmatically from `shared/personas.json` and validated against the v1 schemas, so every number the teacher writes can be checked against the input. Output is `training/data/train.jsonl` (900) and `eval.jsonl` (100), plus a spot-check report. T1 doesn't unlock a showcase level itself; it feeds T2 → M6 (L4).

## Approach (implementation order)
1. **Serve + Spike S4 (task 1-2).** Start the teacher with `unsloth run` (127.0.0.1, tools disabled), thinking off, and check the output has no reasoning text. If Studio can't do that or can't run parallel requests, use `llama-server` (`--jinja`, `-np 4`, `-c 16384`, `--chat-template-kwargs`, `--spec-type draft-mtp`). `training/bench_teacher.py` records single-stream tok/s and aggregate tok/s with 1, 2 and 4 concurrent requests (a few realistic prompts, separate from the pilot). **In Phase A the S4 measurement is single-stream plus a 4-concurrent test, enough to tell whether parallelism helps.** Pass: ≥ 15 tok/s aggregate. Pick the final count and concurrency before Phase B; fallbacks per PDD 14 (~700 examples, shorter autopsies, or 26B-A4B with the owner's OK).
2. **`training/validators.py` (shared by T1, T2, and ported in M6).** Pure functions, no I/O:
   - `parse_naming(text)` → JSON parse + `naming-output` schema (name ≤ 6 words, label enum, `why` ≤ 200). Stray code fences are stripped and the stored target is the **canonical re-serialised JSON**, so the student learns one exact format. Digits in `name`/`why` must appear in the input description; `why` must not mention the hint ("ground truth", "I was told").
   - `check_autopsy(text, facts)` → word count 120-180, **number grounding** (every digit run and `HH:MM` must appear in `facts`; allowed derived forms are the PDD constants {25, 2} and `HH:00` for a trigger `hour`; no percentages, no "1 h 14 min" restatements, no spelled-out numbers), plain text (no markdown, headings or bullets), required structure (headline with deep blocks and residue, strongest stretch, triggers, nudges, one suggestion), and **no outside-browser mentions**. For the "no outside-browser" check I'll use a regex list (offline, away, phone, off-screen, outside, meeting, commute, "away from the keyboard", etc.), tuned with planted-error tests.
   - Territory names mentioned in the autopsy must be names present in `facts` (catches invented territories).
   - Null-field consistency: if `vs7Day` is null, no 7-day/weekly comparison; if `deepBlocks.count` is 0, no claim of a deep block; if `nudges.shown` is 0, no nudge outcome claims.
   - **Coach-voice check** (PDD 4.2): small banned-word list (lazy, wasted, failure, addicted, guilty, shame, "you should have", ...) and no scolding.
   - Token budget: prompt + target fits well inside the student's 2048 context.
3. **`training/gen_inputs.py` (task 3).** Seeded and deterministic (`--seed`).
   - **Territory descriptions (~660 generated, ~600 kept):** per persona/site, perturb origins, path prefixes and counts; mix pure territories, mixed-domain ones (e.g. `/watch` vs `/shorts`), same-origin splits, titles absent (store-titles off), topic tags present/absent (M8 may not exist), and ambiguous cases. Velocity drawn from the persona's ranges for the true label. The **ground-truth label** is kept beside the input (not in the student prompt).
   - **Daily facts (~440 generated, ~400 kept):** coherent by construction: block minutes ≥ 25, `totalMin` = sum, `longestMin` = max, totals consistent, overages only for Drain territories, 5 triggers max, `vs7Day` null for some, `medianReturnMin` null when none accepted. Edge cases: zero deep blocks (`strongestStretch` null), a very good day, a drain-heavy day, no nudges, new user (null 7-day), a single long block. Territory names come from a per-persona name table (the same names the naming task produces, so tasks look consistent).
   - Every object validated against `shared/*.schema.json` (Draft 2020-12), plus a consistency check for facts.
4. **`training/gen_teacher.py` (task 4).**
   - Two teacher prompts holding the coach voice (PDD 4.2), Deep/Shallow/Drain vocabulary, the output structure (4.6, 9.4), few-shot examples, and the hard rules (only numbers from `facts`; browser attention only; no "outside"). The teacher prompt for naming includes the ground-truth label so `suggested_label` is correct; the **student prompt** (what's written to JSONL) is a short fixed instruction plus the input JSON, so the 270M doesn't need the long rules.
   - OpenAI-compatible `/v1/chat/completions` via stdlib `urllib` (no new dependency) with a thread pool sized to `-np`. Resumable: appends one JSON line per result to `training/data/raw/<task>.jsonl` keyed by input id, skips ids already done, logs rolling tokens/s. Retries on transient errors; temperature ~0.7 for variety. The HTTP call is injectable so tests use a stub server.
5. **`training/filter.py` (task 5).** Reads raw outputs, applies the validators plus label-match (naming) and de-duplication of names/near-duplicate autopsies, writes `train.jsonl`/`eval.jsonl` in Gemma chat format (`{"task","id","persona","messages":[user,assistant]}`; Gemma has no system role), **900/100 stratified by task, persona and edge-case tag** (540/60 naming, 360/40 autopsy), and prints a pass-rate report by failure type. Before splitting, near-duplicate **inputs** are removed (canonical hash) so eval isn't a copy of train, and exact duplicate outputs are capped (≤ 5 per name) to avoid mode collapse. It can also emit `train.partial.jsonl` at any time, so T2's S5 spike can start before the full run finishes.
6. **Run + report (task 6).**
   - **Phase A:** generate 10 inputs (5+5, covering at least two personas, one edge case per task), run the teacher on them, filter, and write `docs/showcase/T1/pilot-report.md`: the 10 inputs, outputs, validator verdicts, pass rate, and tokens/s. Then stop.
   - **Phase B (after the owner's go):** start the long run in the background under `caffeinate -i` with the resume command recorded. Write `sample-report.md` (**15 per task = 30**, PDD 10.2's spot-check, including failures the filter caught) once ~100 results exist, and refresh at the end with dataset stats and 3 good examples per task.

## Interfaces and data
- **Canonical student prompt (a contract with T2/M6).** The user turn is a fixed short instruction plus the input object as compact JSON (`separators=(",",":")`, schema property order, numbers as in the object). M6 must build the same string at runtime; the format is recorded in `training/README.md` and the summary, and pinned by a golden-string test. This is the easiest way for T1 to silently break M6.
- **No schema changes.** Reads `shared/*.schema.json`, `shared/personas.json`, `shared/samples/`.
- `training/data/inputs/{naming,autopsy}.jsonl`: `{id, persona, input, meta}` (meta holds the ground-truth label and edge-case tag).
- `training/data/raw/{naming,autopsy}.jsonl`: `{id, output, tokens, seconds}`.
- `training/data/pilot/`: Phase A output (10 examples, same formats, no split). `training/data/{train,eval}.jsonl`: Phase B final chat-format examples as above. Not committed (gitignored); small samples go to `docs/showcase/T1/`.
- Python entrypoints: `uv run python -m gen_inputs|gen_teacher|filter` with `--seed/--count/--resume`.

## Risks and open questions
- **Teacher number discipline** (the 31B may round or restate numbers). Mitigation: strict validator, over-generate ~10-15%, and a regenerate-once path in `gen_teacher` before dropping.
- **GPU contention** with M2's WebGPU spikes tonight/tomorrow; the owner can pause the run (it's resumable).
- **Laptop sleep** kills overnight runs; `caffeinate -i` plus resume.
- **Number-grounding strictness**: a whitelist of {25, 2} is my proposal; spelled-out numbers ("three") are rejected in the prompt rather than validated, since the 270M should write digits.
- **Label-hint leakage:** the teacher sees the true label, so `suggested_label` follows persona priors; ambiguous territories are labelled by site type, not content. Acceptable for a 270M; a limit to state in the post.
- **Synthetic distribution gap:** real titles/paths are messier than persona tables. I'll add noise (missing titles, odd path prefixes), but it stays a known limit.
- **Pilot size:** 10 examples can't show rare failures (e.g. outside-browser mentions at 2%), so the pilot proves the pipeline and gives a first look at quality, not a pass rate. The Phase B count (default 1,000) is decided after the pilot.
- **Questions for the owner:** none blocking. Starting `unsloth run` or `llama-server` is a local, 127.0.0.1-only process with no install.
