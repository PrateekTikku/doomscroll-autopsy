## Approach (one commit per item)
1. **GRU** (`lib/ml/gru.ts`, `gru-train.ts`, `gru-service.ts`). Per PDD 9.6: input per bin = learned territory embedding (16d) + label one-hot (4) + 7 velocity features (standardised with training stats) + time of day sin/cos + minutes in current territory + minutes since last Deep + nudge-shown flag + last nudge response one-hot; last 40 bins; 1-layer GRU, hidden 64; two heads (next-bin territory; occupancy over the next 20 bins → `predicted_t`). Both heads read the final hidden state; loss is the sum of the two cross-entropies. **Training with TF.js** (`@tensorflow/tfjs`, WebGPU backend, CPU fallback; S3) in the offscreen document, which reads IndexedDB itself, nightly (job step) or via a dashboard button. **Inference in plain TypeScript** from stored weights (≈ 30k parameters, 40 steps), so the service worker never loads TF.js; a test proves the TS forward pass matches TF.js's output. Evaluation: train on all days but the latest, evaluate on the latest with the same harness as D-36 (top-1/top-3 next territory, AUC of the spiral score); **promote only if AUC beats Markov, ties go to Markov** (D-20); metrics stored in `models` and shown in the Prediction panel; mode `gru` in the popup/status. If the held-out day has no positives (AUC n/a) the GRU is not promoted. Unit tests: feature builder, TS-vs-TF parity, learns a deterministic synthetic cycle (accuracy well above Markov-free chance), promotion rule, mode selection.
2. **UMAP attention map** (`umap-js`, new dependency): dashboard section, up to ~1,500 sampled vectors from the last retained days, UMAP to 2-D in the dashboard page (seeded, ~2-5 s, cached in memory), SVG scatter coloured by label, click a dot to select its territory (highlights the dots and scrolls to the territory row). Pure helpers (sampling, colouring, selection) tested; headless probe checks it renders on the seeded replay (the seed has vectors only for territory centroids, so the probe synthesises vectors around them).
3. **Topic tags (PDD 9.3)**: fill `assets/topics.json` to ~300 phrases; embed them once as text (the `topic-vectors` record in `models`) through the existing embedder; per territory cosine to the centroid → top-3 with score into `territory.topicTags`; show them in the territory list; feed them into the naming description. **Risk:** the 270M was trained with `topicTags` in the prompt (T1); I verify what the training data holds before wiring it in, and gate the naming change on the M6 probe (labels and fallback must not regress), otherwise tags are shown in the UI only.
4. **Breathing pause** (nudge step 3): a 30-second breathing overlay (inhale/hold/exhale text and a CSS-animated circle, `prefers-reduced-motion` respected) reachable from step 2's *Take a breath* button; at max step 3 the escalation reaches it; the response is logged like the others. Settings: max step 3 is already an allowed value; add the choice to the dashboard if absent. Tests on `policy`, copy and UI mount; probe:m4 extended.
5. **Forget a single capture** (PDD 11.4): in Dashboard → Privacy, list the latest 20 observed items (site + path, time; titles only if stored; never text) with a Forget button; cascade through the existing `forget.ts` (delete the sample, recompute its territory's centroid, regenerate affected names/reports). Tests in `privacy.test.ts` style; probe check.

## Spikes first

Fallback: fewer windows/epochs, then CPU; if it still can't meet the budget, ship the code behind "not promoted" with the honest numbers and say so (the Markov path is untouched either way).

## Test plan

Privacy: no new stored text, no new network.

## Risks and open questions
- TF.js bundle size in the offscreen document (+~1.5 MB); it loads only when training.
- The GRU may simply not beat Markov on a few days of data; that is an acceptable, reported outcome (D-20).
- Topic tags may disturb the fine-tuned naming (see item 3 gate).
- Real-data evaluation of everything needs days of the friend's/owner's browsing; I measure on replayed personas.

## Out of scope
Could-tier items (768d experiment, tag accuracy eval, quiet hours, shortcut). No retraining of the 270M.
