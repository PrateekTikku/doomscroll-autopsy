# M4 — Spiral prediction, nudges, replayer and demo mode (plan)

## Understanding
M4 closes the product loop on top of M3's territories: a spiral score (predicted Drain minutes beyond the remaining allowance over the next 10 minutes, PDD 9.5) computed in **rules mode** (cold start) and **Markov mode** (first-order over territories + internal `away`/`idle`), a nudge policy and in-page ladder (step 1 banner, step 2 blur), and a **replayer + synthetic-day generator + demo mode** so a spiral can be tested and shown on cue without waiting for real data. An evaluation harness compares rules vs Markov (next-territory top-1/top-3, spiral AUC) on the held-out latest day and stores it in `models`. Unlocks **Showcase Level 2**.

## Approach (milestone task order)
1. **`lib/ml/rules.ts` (task 1).** `drainShare = σ(b + w·x)` over `items_per_min`, `scroll_px_s_mean`, `video_skip_rate` (normalised), a feed prior (territory effective label is Drain, or the current item matches `feed-origins.json`), log-minutes in the current territory, and "left a Deep territory in the last 5 min". Constants hand-tuned and documented in the file. Predicted Drain minutes = `10 × drainShare`, attributed to the current territory if it is Drain, else to the user's largest Drain territory today (the policy still blocks nudges outside Drain, so this only affects the displayed score).
2. **`lib/ml/markov.ts` (task 2).** Counts over consecutive 30 s bins (a missing bin breaks the sequence, so gaps are never counted as transitions). States = territory IDs + `unassigned` + `away` + `idle`. Laplace smoothing with a small α (0.05; α = 1 would drown a 15-state matrix, noted in the file). Rollout: propagate the state distribution 20 steps and sum expected occupancy → `predicted_t` minutes. Counts persisted in `models` (`markov`), rebuilt from all retained bins nightly and on demand; top-1/top-3 next-territory come from the transition row.
3. **`lib/ml/scoring.ts` (task 3).** `remaining_t = max(0, allowance − drainMinutesToday_t)`, `excess_t`, score = Σ excess / 10, capped at 1. `selectMode()`: rules until Markov has ≥ 1 day of bins (default: bins spanning ≥ 24 h **and** ≥ 240 labelled bins; GRU promotion is M8), then Markov. **Effective label** = confirmed label, else the M3 `suggestedLabel` (PDD 4.3: hour-0 detection must work before the owner has labelled anything; D-13 treats unconfirmed as lower weight). Items with no territory yet are scored by origin against `feed-origins.json` with the default 15 min allowance.
4. **Evaluation harness (task 4).** Pure `lib/ml/eval.ts` (top-k, rank-based AUC with ties, spiral labels: "actual Drain beyond allowance ≥ 5 min in the next 10") and `lib/ml/evaluate.ts` (reads bins/territories, trains Markov on all days but the latest, evaluates both modes on the latest day, writes `models/eval`). With only one day of real data (today) it falls back to a chronological 70/30 split of that day and **says so** in the stored record. Rules has no territory predictor, so its next-territory baseline is persistence (top-1 = stay; top-3 = stay + two most frequent). AUC with no positives is reported as "n/a", not zero. A button in the dashboard replay panel runs it on real data; `scripts/m4-eval.ts` (run with `npx tsx`, like `c1-bench`) runs it on 14 synthetic days per persona for the showcase table (honest caveat in the results: synthetic days test the harness, not the product).
5. **`lib/nudge/` (task 5).**
   - `policy.ts` (pure): inputs score, threshold from settings, `now`, last nudge, effective label, remaining allowance, `maxNudgeStep`, quiet hours (the setting already exists). Rules: score ≥ threshold, 15 min cooldown, never in Deep/Shallow or within the allowance. Escalation to step 2 when the previous nudge (≤ 60 min ago) was ignored or snoozed and the score is still above threshold after the cooldown; a "back" response resets to step 1.
   - `ui.ts` (shadow DOM, closed): banner (**Back to it** / **5 more min**) and blur. The blur is a fixed full-viewport layer with `backdrop-filter: blur`, so the page DOM is never modified. Styles are applied via a constructable stylesheet (not subject to page CSP) with inline-style fallback. Coach-voice copy in `copy.ts` (PDD 4.2). Mounted by `entrypoints/observer.ts` only after the blocklist/pause checks pass, so blocklisted or paused pages can never show or receive a nudge.
   - `service.ts` + `background.ts` (`registerNudges(router)`): a 30 s alarm builds the current state (latest sample's territory from the online assignment, so K-16's one-minute bin lag does not matter; last closed bin's velocity features), scores it, asks the policy, sends `nudge-show` to the active tab of the focused window (nothing is logged if no tab can receive it), and logs `nudges` (`ts`, `step`, `score`, `mode`, `response`, `secondsToReturn`). `secondsToReturn` is set when a later bin lands in a Deep territory (within 30 min, else null). The 1 min sweep also copies `nudgeShown`/`nudgeResponse` onto the matching bin.
   - Messages: `nudge-show` (background → content), `nudge-response` (content → background), `spiral-status` (popup → background). **`Target` in `lib/messaging` gains `'content'`** (one-word change to an M0 file).
6. **`lib/replay/` (task 6).**
   - `synthetic.ts`: from `shared/personas.json`, a seeded generator for a day of **recorder-format `PipelineEvent`s** (tab/focus, item, scroll, heartbeat, video events at the persona's velocity ranges; spiral triggers from the persona), plus a territory table keyed by `origin + pathPrefix` with labels and allowances.
   - `replayer.ts`: feeds events through the real `step()` pipeline (pure, deterministic) on a **virtual clock** at any speed, resolves territories by longest `origin + path-prefix` match (for a real JSONL recording the table is built from the majority territory per origin/path segment in `samples`), then runs scoring and the nudge policy on each closed bin. **Replays never write to the real stores** (no samples, bins or nudges); their results live in memory and can be downloaded.
   - `demo.ts` + `entrypoints/dashboard/replay.tsx` (mounted with one line in `main.tsx`, as in M3): a prepared ~90 min day (deep work, a Slack break, then a Reels spiral) played at 60× (≈ 90 s), nudges sent to the active tab through the real path, with a **Replay** pill on every replayed nudge, a banner in the dashboard panel and in the popup (flag in `chrome.storage.session`). If no tab can receive the nudge, the panel renders it itself. Also: load a recorded JSONL, run the evaluation, download the result.
7. **Popup (task 7).** Current mode (rules / Markov) and spiral score (0–1, with the sensitivity threshold beside it), from `spiral-status`. The dashboard replay panel also shows the active mode and the last stored evaluation (PDD 4.3: the dashboard always shows which mode is active).

## Test plan
- **Vitest (acceptance 1):** Markov rollout on a known 2-state chain (analytic occupancy), a gap not counted as a transition, Laplace smoothing; allowance logic (within allowance → 0, over → positive, cap at 1, per-territory sum); rules monotonic in velocity and in the feed prior; `selectMode` boundary; policy table (cooldown at 14:59 vs 15:00, Deep/Shallow never, within allowance never, `maxNudgeStep` 1 never escalates, quiet hours, ignored → step 2, back → step 1); eval metrics on toy data (AUC 1.0 / 0.5 / ties, top-k, no-positive case); synthetic generator is deterministic per seed and its events replay to bins with the planned territories; copy contains no mention of time outside the browser.
- **Acceptance 2 (demo):** a unit test replays the demo day on the virtual clock and asserts the banner at the planned virtual time and the blur after the cooldown, plus a headless probe (`M4=1 npm run probe:s1`) that starts the demo on a page and checks both layers appear with the Replay pill.
- **Acceptance 3 (real data):** owner step, like M3: `npm run live`, reload, Dashboard → Replay → "Evaluate on my data"; the stored `models/eval` record shows both modes (and which split was used). The headless probe checks the same code path on its own recorded data.
- `npm run build && npm test && npm run compile && npm run smoke` stay green.

## Risks and open questions
- **Little real data:** the owner has about one day of territory-labelled bins, so the real "held-out latest day" comparison will use the 70/30 within-day split and AUC may be undefined if the held-out part has no Drain minutes beyond allowance. The synthetic table is the main showcase number; I will not present the real one as more than it is.
