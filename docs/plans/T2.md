## Understanding
Turn T1's 973 train / 100 eval examples into a fine-tuned Gemma 3 270M that does the two narrow tasks (territory naming JSON, 120–180-word autopsy), prove it beats its baselines on the 100 held-out examples, and convert it to ONNX q4f16 that generates in a plain Transformers.js page. Unlocks the model half of **L4**; M6 does the integration. Deliverable is also an honest verdict against the PDD 10.4 ship bar, even if it fails.

## Approach (implementation order)
1. **S5 spike first (task 1).** 50-step toy LoRA on 100 train examples, then ONNX export, then a plain HTML page. Try the training paths in this order and stop at the first that completes: (a) scripted Unsloth (`unsloth train` CLI or `FastLanguageModel` from the Studio venv; MPS or MLX backend); (b) Unsloth Studio UI; (c) `mlx-tune`. Record which one worked and why the others didn't (V-05). Then convert the toy merged model: `optimum-onnx`/`optimum` export (or the Transformers.js `scripts/convert.py` path from Google's Gemma 3 270M guide), quantise to q4f16, load with Transformers.js on WebGPU in `training/onnx_test/index.html` served locally, and generate (V-06). **Pass bar:** 50 steps finish; the page generates text. **Fallback:** the PDD 14 list (mlx-tune; alternative export paths until Oct 16 noon). If export is stuck by then, ship the safetensors and tell M6 the 270M can't go in the browser yet (template autopsy + baseline names remain).
2. **`training/finetune.py` (task 2).** LoRA r16 / alpha 32 / lr 2e-4 / 3 epochs / max len 2048, loss on assistant tokens only, Gemma chat template, using whichever path S5 chose. Seeds fixed, loss curve logged to `docs/showcase/T2/training-curve.csv`. Hold out nothing extra (eval.jsonl is the test set); a 5% slice of train is used for a validation loss only. Merge the adapter and save safetensors to `training/data/models/` (gitignored). One full run should take well under an hour at this size; a second run for LR/epochs only if the first misses the bar.
3. **`training/eval/` (task 3).**
   - `rubric.md`: 1–5 on factual faithfulness, structure, voice (PDD 10.4).
   - `run_eval.py`: generates outputs for the 100 eval inputs for each system: **baseline name** (`<top origin> · <top topic or top path segment>`), **template autopsy** (a Python rendering of `facts`, same wording as M5's will be; kept simple and labelled as the baseline), **base 270M** (same student prompt), **fine-tuned 270M**, and the **teacher** output already in `eval.jsonl` (ceiling).
   - `metrics.py`: automatic metrics by reusing T1's `validators.py` (JSON validity, grounding, length, outside-browser rate which must be 0).
   - `judge.py`: serves the 31B again via `llama-server` (same S4 command, 127.0.0.1) and scores every output against the rubric, blind to system identity, temperature 0.
   - `report.md` with the comparison table, plus `review_20.md`: 20 side-by-side examples (10 per task) for the owner.
4. **`training/export_onnx.py` (task 4).** Merged safetensors to ONNX q4f16, load-check in the test page with Transformers.js (the same major version as the extension, `^4.3.1` from `extension/package.json`), generate on both tasks, record file size and tokens/s on WebGPU into `docs/showcase/T2/`.
5. **Model card (task 5).** `training/model_card.md`: Gemma 3 derivative, Gemma Terms of Use text and use restrictions included, data description (synthetic, Gemma 4 31B), eval table. **I do not publish.** Publishing, the repo name and the pinned commit hash are a separate explicit yes from the owner.

I'd install them into a **separate venv under `training/`** (`uv add --group train/export`), never into Unsloth Studio's own venv. This changes `pyproject.toml`/`uv.lock`. **Needs your OK.**

- **Small eval set:** 100 examples (60 naming / 40 autopsy) gives wide confidence intervals; the report will show counts, not just means.
- **Autopsy at 270M:** the grounding check may fail on invented numbers. If so, the verdict is "naming only + template autopsy", which the PDD already allows.
