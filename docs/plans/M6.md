# M6 — Integrate the fine-tuned 270M (plan)

**Approved:** 2026-10-16 23:00 by owner (delegated; self-reviewed against the milestone's tasks and acceptance criteria)

## Understanding
Territory names, suggested labels and the nightly autopsy come from our fine-tuned Gemma 3 270M (T2: 324 MB ONNX, 8-bit weights + fp16 activations, ≈118 tok/s), run in the offscreen document on WebGPU, loaded on demand and unloaded after use. Every output is validated and falls back deterministically (baseline name + rule-based label; M5 template autopsy). The dashboard shows which source wrote each name and autopsy, and the fallback rate is measured. Unlocks Showcase L4.

## The one blocker, and how I'm handling it
The model is **not on Hugging Face** (T2 left publishing to the owner, who is unavailable; publishing needs his explicit yes, the agent instructions). So M6 loads the model from a **configurable source**: `bundled` (default: the ONNX folder copied into the extension at build time by `scripts/copy-model.mjs` from `training/data/runs/run1/onnx_final`, gitignored, so a Load-unpacked install works offline) or `hf` (repo + pinned commit, wired but unused until the owner publishes). If the files are absent the writer reports "unavailable" and everything falls back. This is a deviation from PDD 9.4/10.5 (download from HF), recorded as **D-58**; switching to HF later is a one-line config change. The popup's model status shows the writer's state.

## Approach (in order)
1. **Contract port** (`lib/gen/prompt.ts`): `studentPrompt(task, obj)` = T1's `common.student_prompt` (instruction + blank line + compact JSON, schema key order). Golden test against real lines from `training/data/eval.jsonl` (copied to a small fixture).
2. **Validators** (`lib/gen/naming-validate.ts`, extend `lib/metrics/validate.ts`): port `parse_naming` (JSON/fences, schema by hand, grounded numbers, name-not-URL, hint leak, outside-browser, tone) and the strict checks from `training/eval/metrics.py` (K-07: nudge counts/states, 7-day sign, allowance claim, invented trigger pair). Tests incl. planted errors from the T2 review.
3. **Generation host** (`lib/gen/{config,generator,host,messages}.ts`, registered in `entrypoints/offscreen/main.ts`): Transformers.js `AutoTokenizer` + `AutoModelForCausalLM`, `dtype: fp16`, exactly the evaluated settings (chat template on one user turn, greedy, 120 / 400 new tokens); a sampled variant for the retry; messages `generate`, `gen-status`, `gen-unload`; unload 30 s after the last request and explicitly at the end of a job.
4. **Naming** (`lib/gen/naming.ts`): build a schema-valid `TerritoryDescription` from stored samples/bins (top 5 origin+first path segment, ≤ 5 titles if stored, velocity, minutes on the latest active day), generate → validate → retry once (sampled) → fall back to the baseline name and the rule-based label. Writes `name`, `suggestedLabel` and new optional fields `nameSource`, `nameKey` on `TerritoryRecord`; only unconfirmed territories are renamed (confirmed ones are never changed). `buildTerritories` keeps a model name while the top origins are unchanged (`nameKey`), so a re-cluster doesn't throw it away.
5. **Autopsy** (`lib/gen/autopsy.ts`): prompt from `facts` → generate → `checkAutopsy` + strict checks → regenerate once (sampled) → template. `generateReport` takes a writer; `report-generate` and the nightly job (new step between re-cluster and reports) use model-first. Report keeps `modelVersion` (model id or `template`) and new optional `source` (attempts, error codes).
6. **Dashboard/popup**: autopsy pill "Written by Gemma 3 270M (fine-tuned)" vs "Written from a template (model output failed checks)"; territories list shows a subtle "named by the model / baseline name" tag; a button "Name territories with Gemma"; popup line for the writer model. A stats record (`models/gen-stats`: attempts, model successes, fallbacks per task) feeds a small "Writer model" row in Developer.
7. **Evidence**: `scripts/m6-probe.mjs` (`npm run probe:m6`): headless Chrome, bundled model, seeds persona territories + samples + 8 replayed days, runs naming and autopsies through the real service worker → offscreen path, and (a) checks the extension's raw output equals T2's browser output for the same prompts (determinism/contract), (b) records the fallback rate over 6 personas × 2 days and the naming results, (c) writes `docs/showcase/M6/` (model-written vs template for the same day, naming examples, rate).

No `shared/` change, no `DB_VERSION` bump. Optional fields: `TerritoryRecord.nameSource?: 'model'|'baseline'`, `nameKey?: string`, `suggestionSource?: 'model'|'rules'`; `ReportRecord.source?: {kind:'model'|'template'; attempts:number; errors:string[]}`. New messages `generate`, `gen-status`, `gen-unload` (offscreen), `gen-name-territories` (dashboard → background). New `models` record `gen-stats`.

## Spikes first
**G1: the model loads and generates inside the extension's offscreen document** (local `chrome-extension://` model files through Transformers.js, no Cache API for local files, fp16 on WebGPU, external-data file). Pass bar: output byte-identical to T2's browser output on 5 eval prompts, load < 10 s, no exceptions. Fallback: if local-path loading fails, serve the files through a blob/fetch override; if WebGPU can't hold both models, unload the embedder while generating. If neither works the milestone ships the validators, fallbacks and UI with the model reported "unavailable", and says so.

## Test plan
Unit: prompt golden vs training fixture; naming/autopsy validators (planted errors from T2: swapped nudge counts, wrong 7-day sign, invented trigger, allowance claim with none); naming description builder is schema-valid (Ajv in tests); retry-then-fallback paths with a fake generator (invalid JSON → retry ok; invalid twice → baseline; autopsy fails strict → template; generator throws → template; model unavailable); `buildTerritories` keeps/drops model names; nightly step order. Probe G1 and `probe:m6` as above. Regression: build, test, compile, smoke, `probe:m5`, `probe:m4`.

## Risks and open questions
- Bundled 324 MB makes the unpacked extension ~350 MB; fine for Load-unpacked (D-26), to be revisited if the owner publishes to HF (M7 packaging).
- Memory: embedder + writer resident together; the writer unloads after use. I'll record the numbers I can measure in headless Chrome (K-09).
- Autopsy strict-clean was 70% in T2, so a ≈ 30% fallback rate is expected; reported, not hidden.

## Out of scope
Retraining (K-08, handled separately as an optional follow-up), topic tags, publishing to Hugging Face or DEV (needs the owner's yes).
