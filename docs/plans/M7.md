# M7 — Release candidate and first user (plan)

**Approved:** 2026-10-17 by owner (delegated: the owner is unavailable and asked me to review and approve my own plans; reviewed against `implementation-milestones.md` M7, PDD 4.3, 11.1, 11.5, 16.4)

## Understanding
Make the build installable by one real friend on an Apple Silicon Mac: an onboarding page that says honestly what is observed and stored, a README install path, a zip, a fresh-profile end-to-end smoke test and an interview template. No new features. Unlocks Showcase Level 5 (the owner confirms the friend installed and runs the interview; I can't).

## Approach
1. **Onboarding page** (`entrypoints/onboarding`, replaces the stub). Sections: what is observed (origin, path, dwell, scroll, video events; item text and thumbnails only in memory to embed, then discarded); what is stored (vectors + metadata, 30-day retention, titles optional; no text/screenshots/query strings) with the honest wording of PDD 11.1 (vectors are *not anonymous*; claim = "never leaves your device"); the install warning ("read and change all your data on all websites") explained; requirements (Chrome on a WebGPU-capable machine, K-11; ~350 MB writer bundled; the nightly job needs Chrome running, K-22; browser-only by design); **model status** with a "Download and start now" button and progress bar (EmbeddingGemma 2 ~255 MB from Hugging Face, the only network traffic) and the writer's bundled state; **blocklist review** (shows the default categories, embeds the existing editor logic from `lib/privacy/blocklist-edit.ts` for add/remove); sensitivity picker; "Done" stores `onboarded` and opens the dashboard.
2. **Opens on install:** `onInstalled` with `reason === 'install'` opens `onboarding.html` in a tab. Link "Welcome / how it works" in the popup footer and dashboard so it can be reopened. New setting-free flag `onboardedAt` in `chrome.storage.local` (own key, no `Settings` shape change).
3. **Warm-up hook:** new offscreen message `embedder-warm` → `host.warm()` (calls `ensure()`), background message `embed-warm`. Needed because the embedder otherwise loads only on the first item. Tested with the host's fake loader.
4. **README:** install via zip / Load unpacked, first run, what to expect on day 1 (cold start stages), privacy, limits, uninstall/wipe.
5. **`npm run zip`** (WXT) → copy to `releases/doomscroll-autopsy-<version>.zip` via a small script; record path, size and sha256. Verify the zip contains the model and `ort/` files and unzips into a loadable folder. Bump version to 0.2.0 (RC).
6. **Fresh-profile smoke test** (`scripts/m7-probe.mjs`, `npm run probe:m7`): from the *unzipped release* in a throwaway headless Chrome profile: onboarding opens automatically; warm-up downloads/loads the embedder (or reports it); seed a replayed persona day (reusing M5's `probe-seed.json` approach) to get territories/metrics fast; check popup metrics, a nudge (demo mode), forget (range + site), wipe. Fails on exceptions. Checklist recorded in `docs/showcase/M7/`.
7. **Release-blocking bugs only**, recorded.
8. **`docs/first-user/interview.md`:** the 5 PDD 16.4 questions plus a short setup/observation sheet and answer template. Owner conducts it.

## Spikes first
**R1 zip size/loadability:** does `wxt zip` handle a ~700 MB tree and does the unzipped folder load? Pass: zip builds, loads, probe passes. Fallback: custom `zip -r` script; if the size is a real problem, document "ask the owner for the zip via AirDrop/Drive" (not a code change).

## Test plan
Vitest: onboarding state helpers, warm-up host behaviour, copy contains the honest-wording claims (and not "anonymous" claims). `npm run build/test/compile/smoke/check:types`, `probe:m7` on the unzipped release, regression `probe:m5`/`probe:m4`. Privacy check: grep the built onboarding for any network call other than the model host.

## Risks and open questions
- The friend's machine/Chrome version is unknown; WebGPU absence gives no embeddings (K-11), so onboarding includes a WebGPU check with a plain message.
- Headless download of the embedder needs network; the probe tolerates offline by reporting.
- Publishing the model to Hugging Face stays out (outward-facing, needs owner's yes); the zip bundles the writer (D-58).
- Cannot verify the friend installed or run the interview: left to the owner.

## Out of scope
New features, Chrome Web Store, publishing to HF/DEV, M8 items.
