# M3 — Territories and labeling (plan)

## Understanding
M3 turns the 256d vectors M2 writes into **territories**: k-means groups (our own code) that keep their ID, name, label and allowance across re-clusters via Hungarian matching. New samples are assigned online to the nearest territory; vectorless samples inherit the previous item's territory (K-12). The dashboard gets a territory list where the owner confirms a Deep / Shallow / Drain label and sets a Drain allowance, plus a dev view showing one domain split into several territories against a domain-only baseline. Unlocks **Showcase Level 1**.

## Approach (milestone task order)
1. **`lib/ml/kmeans.ts` (task 1).** Spherical k-means on unit vectors: distance = 1 − dot, centroid = mean re-normalised, k-means++ init with a seeded PRNG (deterministic tests), 3 restarts, ≤ 50 iterations, empty-cluster re-seed. `silhouette()` and `chooseK()`: k ∈ [4, min(30, ⌊n/15⌋)]; pick the smallest k whose silhouette is within 0.02 of the best (the "small bias toward fewer"). **k selection runs entirely on a ≤ 1,200-point random subsample** (k-means for each k plus silhouette; on all 6,000 points the 27 candidate k × 3 restarts would cost ~100 G multiply-adds, far over budget). Only the final fit at the chosen k uses all points (cap: most recent 6,000 vectors). Clusters with < 5 members (or < 0.5% of samples) are dissolved: their points go to the nearest remaining centroid, so the list isn't cluttered with outlier territories.
2. **`lib/ml/hungarian.ts` (task 2).** Munkres O(n³) for rectangular matrices (pad), maximising centroid cosine. `matchTerritories(newCentroids, old)` keeps ID/name/label/allowance for pairs with similarity > 0.8; the rest get new IDs. Old territories with no match are dropped (their samples are reassigned by the new run) **unless the owner confirmed their label**: those are kept as-is, with their old centroid, so a changed k can never silently erase a confirmation. They show as "dormant" in the list (no new members unless they win nearest-centroid) and can be deleted by hand. This replaces the earlier "delete unmatched" default.
3. **Assignment + scheduling (task 3).** `lib/ml/territories.ts`:
   - `assignSample(vec, territories)`: nearest centroid; if distance > the territory's `radius`, leave `territoryId: null` ("unassigned"), always storing `territoryDist`.
   - `syncAssignments()`: scans only samples newer than a stored watermark (`lastSyncTs`, minus a 2-min overlap) because IndexedDB can't index `null`; assigns vectored samples with no territory, carries the previous sample's territory to vectorless ones (time order), then sets `bins.territoryId` (the territory covering most of the bin, from sample intervals `[ts, ts+dwell)`). Runs after every re-cluster, on dashboard open, and on a 1-min alarm.
   - `recluster({force})`: loads vectors (768d dev-mode rows are truncated with `truncateAndNormalize`), `chooseK`, k-means, Hungarian, then writes territories (centroid, size, radius = p95 member distance × 1.25, firstSeen/lastSeen), re-labels all samples and bins. Guarded by a lock; online assignment and sync skip while it runs and a sync sweep follows. Run state (`lastRunAt`, `firstVectorTs`, `lastSyncTs`, k) lives in the `models` store under `territories-meta`. "Day 1" = the first 24 h after `firstVectorTs`.
   - `lib/ml/territories-background.ts`: `registerTerritories(router)` with a 30-min `chrome.alarms` check. Due when: first run at ≥ 300 vectored samples; every 2 h while on day 1 (until the first nightly run); then once per day after 03:00 local, or at the next wake (PDD 6.3 allows this). Messages: `territories-recluster` (dashboard → background, forced; minimum 60 vectors so the owner can test early) and `territories-sync`.
4. **Baseline naming (task 4).** `"<top origin> · <top path segment>"`: host without `www.`, first path segment most common among members, ignoring ID-like segments (digits/long hashes), `/` → "home". Names refresh on re-cluster only for territories the owner hasn't confirmed.
5. **Rule-based suggested labels (task 5).** ≥ 50% of members match `assets/feed-origins.json` (origin + `pathPatterns`) → `drain`; ≥ 50% on a chat/mail/calendar origin list (new `assets/shallow-origins.json`: Slack, Discord, Teams, Google Calendar, Outlook, Linear…) → `shallow`; else none. Stored in `suggestedLabel` only; `label` stays null until the owner confirms. UI marks it "suggested".
6. **Dashboard territory list (task 6).** New `entrypoints/dashboard/territories.tsx`, mounted from `main.tsx` with a one-line change (M5 owns the rest of the dashboard). Per territory: name, size, top 3 origins, today's minutes (sum of today's bins' `active_s` by territory), three label buttons, allowance input for Drain (default 15 min, written when set to Drain), and confirmed/suggested state. "Re-cluster now" button. Reads/writes IndexedDB directly (same origin), like the existing Developer section.
7. **Evidence (task 7).** Dashboard dev view (dev mode) `entrypoints/dashboard/evidence.tsx` plus pure `lib/ml/evidence.ts`: for each origin, the territories it spans with share and top path segment; the best "one domain, many territories" example; and a baseline comparison on the same vectors: mean silhouette of grouping by domain vs. by territory (cohesion/separation), plus the share of samples per origin that land in a different territory than the origin's majority. Territories are fitted to these same vectors, so beating domain grouping on silhouette is partly by construction; the report says so, and leans on two non-circular checks: (a) **path agreement**: within a split domain, how well the territories line up with URL path segments the clusterer never saw (e.g. `/shorts` vs `/watch`; normalised mutual information); (b) **the Deep/Drain split**: the headline example prefers a domain whose territories carry different labels (the owner's confirmed ones, else the rule-based suggestions), which is the L1 story. "Download evidence JSON" exports counts only (no titles, no text). Numbers and the example go to `docs/showcase/M3/results.md`. The JSON still lists origins and path segments (browsing history, not item text); the owner reads it before anything from it is used in the post.

## Test plan
- **Vitest (acceptance 1):** k-means recovers 5 planted, separable clusters (purity 1.0); `chooseK` picks the planted k on synthetic data (k = 4, 7, 12) and prefers fewer on near-ties; Hungarian: permuted assignment, rectangular case, below-0.8 pair stays unmatched; **IDs, names, labels and allowances survive a re-cluster** (including after shuffling the input and after a small centroid drift); unassigned threshold; vectorless carry-over; bin majority; baseline names; suggested labels; evidence maths; privacy scan of stores.
- **Real data (acceptance 2):** `npm run live`, reload, browse, then Dashboard → Territories → "Re-cluster now": territories appear; set labels, force a second re-cluster, labels and allowances persist. Owner step in the review.
- `npm run build && npm test && npm run compile && npm run smoke` stay green; the smoke script opens the dashboard.

## Risks and open questions
- **Little real data:** vectors only exist since M2 (today). If the owner has < ~300 vectored samples, clusters will be coarse. The forced 60-vector minimum and an honest note in the evidence cover this; real use on Oct 17 improves it.
- **Service worker limits:** a long re-cluster could be cut off; C1 decides where it runs. Re-cluster is atomic (one write transaction at the end), so an interrupted run changes nothing.
- **The 0.8 match threshold** is the PDD's number but untested on real EmbeddingGemma centroids; C2 measures it. A too-lax value could hand a label to the wrong new cluster; a too-strict one loses labels (hence the dormant-confirmed rule).
- **Schedule:** ~6 h is a large share of Fri Oct 16 with M4 next and the Sat freeze. If we run late, I'd cut the evidence extras (path-agreement NMI, JSON download) first and keep the Deep/Drain example.
- **Bin territories are swept, not live,** (1-min alarm). M4 may want them event-driven; noted for M4.
- **Open questions (defaults in bold, change if you disagree):** (1) unmatched territories are dropped, except owner-confirmed ones, which are kept dormant; (2) the evidence compares embeddings against domain-only grouping by silhouette on the same vectors, since there is no ground-truth labelling; OK?
