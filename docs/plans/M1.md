# M1 — Observer, bins and storage (plan)

> Owner decisions taken before writing (2026-10-15): **stable live copy** for the daily profile (`npm run live`), **dynamic content-script registration** with `excludeMatches`, **S1 = automated probe + owner's 10-min check** on logged-in sites, **away/idle bins for the first 10 minutes of an absence, then a gap**.

## Understanding
M1 makes the extension watch browsing per PDD 7 and store **samples** (metadata of each item in view) and **30-second bins** (velocity features), so the owner's real data starts accumulating today. No models: vectors stay `null` until M2. It also adds the dev-mode recorder (the event stream M4's replayer consumes), pause with a toolbar badge, and a popup with live counts. Privacy is part of the core: blocklist and pause checks come first, and no item text, query strings or screenshots are ever stored. It doesn't unlock a showcase level by itself, but it is the data source for L1.

## Approach (implementation order → milestone tasks)
1. **Gatekeeping (T1, T5).** Pure functions in `lib/observer/`:
   - `isBlocked(hostname, blocklist.json, settings.blocklist)`: domains/subdomains, suffixes, keywords, plus user adds and removals.
   - `excludeMatchesFor(...)`: `*://*.<domain>/*` and `*://*.<suffix>/*` patterns (keywords can't be expressed).

   The content script is registered **at runtime** (WXT `registration: 'runtime'` + `scripting.registerContentScripts`) with those `excludeMatches`. It is re-registered on install/startup and whenever `settings.blocklist` changes. Its first action is still `getSettings()` and then checks for incognito, a non-http(s) URL, a blocked host, or pause. On a match it reads nothing and attaches no page listeners (only a `storage.onChanged` listener when paused, so it can resume). On install or update it is injected into already-open eligible tabs, and orphaned scripts from an old version stop quietly.
2. **Content observer (T1).** `startObserver()` returns `stop()`, so pause and unpause work live.
   - **Item detection (PDD 7.3):** `elementFromPoint(viewport centre)` runs at most every 250 ms while scrolling, plus on `scrollend`, URL change (1 s poll) and media `play`. It then walks up the ancestors to the first element 30–100 % of the viewport high with ≥ 40 chars of text or a dominant `<img>`/`<video>`. The walk is a pure function over an `ElementLike` interface, so it's unit-tested without a DOM library.
   - **Identity (D-47):** a per-item URL path (`/shorts|reels?|reel|p|status|comments/<id>`) gives `u:<path>`. Otherwise the media `currentSrc` + `duration` + `poster` give `m:<hash>`, else the first 200 chars of normalised text give `t:<hash>`. The hash is a small sync 53-bit hash (our own code, no dependency), so text is never in a key.
   - **New-item rule:** I read 7.3's "previous item was in view ≥ 600 ms" as **an item counts once it has been the current item for ≥ 600 ms**. Fly-by items during fast flicks don't count; `prevDwellMs` is the visible dwell of the previous counted item.
   - **Viewport fallback** (no card found): the viewport is the item. A new sample comes when ≥ 60 % of the visible text blocks changed (sampled at a 3×3 grid, compared by hashes) or after every 60 s of continued activity. Activity is timestamps of scroll, key and pointer events only, never their content.
   - **Signals:**
     - Scroll velocity: capture-phase scroll listener (catches inner containers like Shorts), EMA smoothing, sent ≤ 1/s while moving plus a final 0.
     - Video: the dominant `<video>`; `play`/`pause`/`ended`, and `skip` when left before 2 s or before 25 % watched.
     - `visibility` events.
     - `heartbeat` every 15 s while visible.
     - Item text: `innerText`, normalised, ≤ 2,000 chars, sent **in memory only**. The service worker drops it on receipt in M1; M2 routes it to the embedder.
   - **Dev mode:** console logs of each item (key type, visual, dwell) and the p95 observer cost per scroll event (budget < 2 ms, PDD 9.9).
3. **Service-worker pipeline (T2, T3).** `lib/observer/pipeline.ts` is a **pure reducer**: `(state, event) → (state, outputs)`. It handles observer events (+ `tabId`) and browser events: `tab-activated`, `window-focus`, `idle-state`, `tab-removed` and `tick`.
   - **Clock:** each event first advances time since the last event under the *previous* state.
   - **States:**
     - *active*: window focused, the event came from the active tab within the 45 s pulse window (heartbeat merging), and not idle, **or** idle with a video playing in that tab (D-46). Locked always counts as idle.
     - *away*: no focused window.
     - *idle*: idle without a video.
     - *unobserved*: paused, blocked, a `chrome://` page or no content script. This is a **gap** and is never counted.
   - **Bins:** time is split across 30 s boundaries.
     - Each bin carries the 7.6 features: time-weighted `scroll_px_s_mean`, `items_per_min` (items ÷ 0.5), `mean_dwell_ms`, `video_skip_rate` (skips ÷ videos seen), `tab_switches`, `away_s`, `idle_s`.
     - It also carries the new `active_s`, `away`/`idle` (majority), `territoryId: null` and the nudge fields at their defaults.
     - Away/idle bins are written for the first 10 min of an absence, then nothing; consumers treat missing bins as away.
     - A 30 s `chrome.alarms` tick closes bins; it is cleared after the 10-minute cap and re-created when the user is active again.

   **Adapter** (`lib/observer/background.ts`):
   - Maps chrome events into the reducer, serialises events through a promise queue, and keeps the reducer state in `chrome.storage.session` so service-worker restarts lose nothing.
   - Writes closed bins and samples to IndexedDB.
   - Drops everything while paused (defence in depth).
4. **Samples (T3).**
   - **One per counted item:** `ts`, `tabId`, `origin`, `path` (query and fragment stripped again in the service worker), `title` only if `storeTitles`, `isVisual`, `dwellMs`. `vector`, `territoryId` and `territoryDist` are `null`.
   - **Dwell:** written immediately with dwell 0. It is updated from the next item's `prevDwellMs`, or provisionally on visibility-hidden or tab close.
5. **Recorder (T4).** `lib/replay/recorder.ts`:
   - When `devMode` is on, every reducer input event goes to `recorderEvents` (`text` removed, `title` only if `storeTitles`), so M4 can replay it exactly.
   - `exportJsonl()` for the dashboard's minimal **Developer** section (dev-mode toggle, record count, "Download JSONL", "Clear").
6. **Pause and badge (T5).**
   - The popup offers 15 min, 1 h, until tomorrow (**next 04:00 local**), indefinitely, and Resume. It writes `pausedUntil`.
   - The service worker shows a badge (`II`, amber) while paused and sets a `pause-end` alarm that clears an expired pause. Content scripts stop or start on the settings change.
7. **Popup (T6).** Live counts from a `live-stats` message: samples today, active minutes today, items/min now (last 60 s), and the pause controls. The M0 offscreen check stays as a muted line.
8. **Live install.** `npm run live`: build, then copy `.output/chrome-mv3` to `extension/.live/chrome-mv3` (gitignored). The owner loads that folder once. README and the the agent instructions commands are updated.
9. **Spike S1 (T7).** `scripts/s1-probe.mjs`, a dev tool reusing the smoke script's pipe approach:
   - Headless Chrome with dev mode on visits YouTube Shorts, Reddit and a docs site (MDN), logged out and read only.
   - Each site gets 20 scrolls (or ArrowDown on Shorts). The probe counts recorder `item` events per scroll and reads the p95 cost per scroll event.
   - It also visits a page on a temporarily blocklisted test domain (`example.com` via `addedDomains`) and checks there are 0 events.
   - Finally it dumps every store and asserts no `?`, no `#` and no item text.

   I tune the heuristics against it. The owner then checks Instagram and X in his profile (about 10 min). Results go in `experiments/spikes.md` and `docs/showcase/M1/`.

## Interfaces and data
- **Messages** (merged into `MessageMap`):
  - `observer-event`: payload is `ObserverEvent` from `@shared/types`; reply `void`; `tabId` comes from `sender`.
  - `live-stats`: reply `{samplesToday, activeMinToday, itemsPerMinNow, pausedUntil}`.
- **`PipelineEvent`** (TS only, `lib/observer/types.ts`): `ObserverEvent & {tabId}` or a browser event. This is also the **recorder JSONL line format**, documented in the summary for M4.
- **Storage:**
  - `BinRecord` gains `active_s: number` (seconds of observed browsing in the bin). Without it a half-observed bin would count as 30 s of deep work in M5. No `DB_VERSION` bump: no store or index changes.
  - Reducer state lives in `chrome.storage.session` (`observer-state`).
- **`shared/` contracts unchanged.**

## Spikes first
**S1** (via the probe, then the owner's check):
- **Pass:** a new item for ≥ 90 % of scrolls per site, identity correct on Shorts and Reels (V-12), and p95 observer cost < 2 ms per scroll event.
- **Fallback:** viewport-on-change for any failing site class, recorded in `spikes.md`.
- **If headless runs into consent or login walls:** run the probe headed, or leave that site to the owner's manual check.

## Test plan
- **Unit (Vitest):**
  - `identity` (URL rule, media rule incl. `blob:`, text rule, hashing)
  - `item-detect` walk on fake element trees (card found, too small, too tall, viewport fallback)
  - `viewport` change ratio
  - `velocity` EMA smoothing and decay
  - `video` skip rule
  - `blocklist` (domain, subdomain, suffix, keyword, user add/remove) and `excludeMatchesFor`
  - `url` sanitising
  - pause-until (04:00 rule)
  - pipeline:
    - heartbeat merging within and beyond the pulse window
    - bin splitting across boundaries
    - feature aggregation
    - away/idle states, video-as-active (D-46), the 10-minute cap
    - paused input ignored
  - recorder strips `text`/`title`
- **Privacy test (acceptance):** feed events with item text, `?query` and `#frag` through the real adapter into fake-indexeddb, then scan **every** stored record (samples, bins, recorderEvents) for the text, `?` and `#`. Expect none.
- **Blocked or paused gives no events:** content-script gate tests, reducer ignores input while paused, and the probe's blocklisted-domain check.
- **10 minutes of browsing:** the probe run (about 10 min) plus a store dump; then the owner's real browsing, where popup counts rise.
- **Gates:** `npm run build`, `npm test`, `npm run compile`, `npm run smoke` all green.

## Risks and open questions
- Generic detection may miss on obfuscated or virtualised feeds (Instagram, X). The viewport fallback covers it; the owner's check covers the logged-in sites.
- WXT runtime registration may behave differently under `npm run dev`. The first-action check is always present, and plain manifest registration is the fallback.
- Chrome briefly reports `WINDOW_ID_NONE` when switching windows on macOS. At second-level accounting the effect is negligible.
- "Until tomorrow" = next 04:00 local (confirmed by the owner, 2026-10-15).

## Out of scope
Embeddings and `captureVisibleTab` (M2), territories (M3), nudges (M4), retention, forget and the blocklist editor UI (M5), Readability, any dashboard UI beyond the Developer section, onboarding.
