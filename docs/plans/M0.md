## Understanding
M0 sets up a repo every later chat can build on. It has a WXT + TypeScript + Preact MV3 extension that builds, tests and loads in Chrome with wired-up stub entrypoints, a typed IndexedDB layer, the shared JSON Schema contracts with generated TS types, a `uv` training project that validates those schemas, and the starting asset lists. Its main job is to unblock **Lane B (T1)** and **M1** today. It doesn't unlock a showcase level by itself, but it is the base for L1.

## Approach (in implementation order, mapped to the milestone's tasks)
0. **Spike S0 (10 min):** scaffold WXT 0.21 (latest) + Preact 11 + `@preact/preset-vite`, build, confirm the popup renders. See *Spikes*.
1. **Extension skeleton (T1):** `extension/` uses npm, `wxt.config.ts`, `tsconfig` alias `@shared → ../shared`. Entrypoints:
   - `background.ts`: registers message handlers through a tiny router (`lib/messaging/`) so M4 and M5 can add handler modules side by side without editing the same lines.
   - `offscreen/index.html` + `main.ts`: answers `ping`. `lib/offscreen.ts` has `ensureOffscreenDocument()` (`reasons: ['WORKERS']` as a placeholder until S2/V-07 confirms it; one document only).
   - `content.ts`: empty stub on `<all_urls>`, with a comment saying the blocklist and pause check goes first (M1).
   - `popup/`, `dashboard/`, `onboarding/`: Preact "hello" pages. The popup shows the version, an "Open dashboard" button and a live **SW → offscreen ping** status, which proves the wiring works. The dashboard lists the IndexedDB stores and `DB_VERSION`.
2. **Manifest (T2):** permissions `storage, unlimitedStorage, offscreen, tabs, alarms, idle, scripting` (no `commands`). `host_permissions: ["<all_urls>"]`. CSP `extension_pages: "script-src 'self' 'wasm-unsafe-eval'; object-src 'self'"`. Name and description from the PDD, version 0.1.0.
3. **IndexedDB (T3):** `lib/db/` with `idb`. A `DBSchema` type for `samples` (auto id; indexes `ts`, `territoryId`, `origin`), `bins` (`binStart`), `territories` (`id`), `nudges` (auto; `ts`), `models` (`name`), `reports` (`date`), `forgetLog` (auto), plus **`recorderEvents`** (auto; `ts`) for M1's dev-mode recorder, so M1 doesn't need a version bump. `DB_VERSION = 1` with an upgrade function keyed by `oldVersion`. Thin typed accessors (`openDb`, `put`, `getAll`, `getRange`, `clearAll`). **No `settings` store** (D-52).
   **Settings (from D-52):** `lib/settings/` holds typed defaults (sensitivity `balanced`, maxNudgeStep 2, quietHours null, blocklist additions/removals, retentionDays 30, storeTitles true, devMode false, `pausedUntil: number | 'forever' | null`), plus `getSettings`, `updateSettings` and `onSettingsChanged` over `chrome.storage.local`.
4. **Shared contracts (T4):** draft 2020-12 schemas in `shared/` as described in 0.6: `observer-event` (a `oneOf` on `type`), `territory-description`, `naming-output`, `daily-facts`, plus a `personas.schema.json` for `personas.json`. Each has `$id` ending in `/v1` and `additionalProperties: false`. Refinements, chosen so the T1/M6 grounding validators work on plain strings:
   - Clock times are local `"HH:MM"` strings and `date` is `"YYYY-MM-DD"`.
   - Minutes are integers, and `hour` is an integer from 0 to 23.
   - Territories are referenced by **name** in facts.
   - `naming-output.name` uses a pattern for ≤ 6 words and maxLength 60. `why` has maxLength 200.
   - `vs7Day` is nullable.

   `shared/samples/<schema>.sample.json` holds one valid example per schema, used by both lanes. `personas.json` holds the 6 personas, each with sites per label (origin, path prefix, sample titles), day shape and spiral triggers. `npm run gen:types` (`scripts/gen-types.ts`, run with Node 24's built-in type stripping) uses `json-schema-to-typescript` to write `shared/types.ts`.
5. **Assets (T5):**
   - `blocklist.json`: `{version, domains[], keywords[]}` covering banks and payments (US and India), health portals, password managers, webmail, `.gov`/tax, matched against the hostname.
   - `feed-origins.json`: `{version, feeds[{origin, pathPatterns[], kind}]}` for YouTube (Shorts and home), Instagram, X, Reddit, TikTok, Facebook, LinkedIn feed, and major news sites.
   - `topics.json`: a real list of ~300 unique phrases (cheap to do now; M8 can refine it).
6. **Tests (T6):**
   - Vitest via `wxt/testing` (`WxtVitest`, fake browser) and `fake-indexeddb`, with tests colocated as `*.test.ts`.
   - Real tests: db (open, upgrade, stores and indexes, round trip, Float32Array vector survives), settings (defaults, update, change event), messaging router.
   - One smoke test each in placeholder folders `observer/`, `replay/`, `ml/`, `nudge/`, `metrics/`, `privacy/` (each has an `index.ts` stub).
   - Assets tests check shape, topics count ≥ 280 and unique.
   - `shared` tests: every sample validates (ajv, tests only) and **regenerated types equal `shared/types.ts`**.
7. **Training (T7):** `training/` is a `uv` project with Python 3.13, dev dependencies `pytest` and `jsonschema`, and `uv.lock` committed. `tests/test_shared_schemas.py` checks that each schema is valid, each sample validates, a corrupted sample fails, and personas validate.
8. **Root files (T8):** short `README.md` (what it is, build, Load unpacked, tests), `LICENSE` (MIT, © 2026 Prateek), `.gitignore` (node_modules, `.output`, `.wxt`, `.venv`, `training/data/*` except `samples/`, `*.onnx *.gguf *.safetensors`, `releases/`, caches).
9. **Docs (T9):** `docs/showcase/README.md` explains the per-milestone convention. `experiments/spikes.md` gets one heading per spike (S1–S5), so M1/M2/T1/T2 each fill their own section instead of racing to create the file.

## Interfaces and data
- **Messages:** `{type:'ping'} → {ok, from}` and `{type:'ping-offscreen'} → {ok, offscreen}`. The router type is `registerHandler<T extends Message['type']>(type, fn)`.
- **Storage:** IndexedDB `doomscroll-autopsy` v1 with the 8 stores above. Settings live in `chrome.storage.local` under the key `settings` (D-52).
- **Contracts:** 5 schemas v1 + `personas.json` + `types.ts`. Any later change needs a summary note and an update to every consumer.

## Risks and open questions
- Preact 11 is very new, so preset-vite or prefresh might break. That's what S0 checks, and the fallback is Preact 10.
- Importing `shared/` from outside `extension/` can trip Vite's `fs.allow` in dev mode. I'll configure the alias and allow list.
- **Ajv can't compile at runtime under MV3 CSP** (it uses `new Function`). I'll use it only in tests, and tell M5/M6 to use Ajv standalone code or hand-written validators.
- No open questions left.
